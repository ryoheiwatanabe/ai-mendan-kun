# 根拠を使った回答の生成と校閲

承認済みの情報から、質問に合わせて要約・言い換えを行います。文字版と音声版は同じ回答処理を使い、検証が済んだ本文を表示・読み上げます。

2026年9月18日から、本人用の改善版は `ANSWER_PIPELINE=jev_v1` でJEVの採否判定を使います。短い候補を生成し、機械確認とJEVを通します。公開中サイトへの切替は本人試用後です。以下は手動切り戻し用の `legacy` 経路の説明で、JEV版の設定・確認結果・制約は [JEV版](jev.md) を参照してください。

## legacyの回答処理

1. 質問と直近の会話から関連資料を検索し、所有者・公開範囲・承認・現行版を確認します。会話履歴は話題の理解に使い、事実の根拠にはしません。
2. 回答モデルが候補を作ります。原文段落の引用と名前の回答に加え、根拠の引用を付けた要約・言い換え・限定的な見立てを扱います。
3. 表示文と主張の対応、根拠ID、引用の実在、数字、文字数を検証します。
4. 同じProviderで、主体・時点・否定・例外・単位・担当範囲を保っているか、質問に答えているかを校閲します。校閲モデルは合否だけを返し、候補本文を書き換えません。
5. 公開状態を再確認してから本文を表示します。音声の生成・配信中も根拠の変更と中断を確認し、撤回後の音声は送りません。

一般質問の通常経路は、回答生成1回と校閲1回です。修復生成は最大1回に制限し、回答生成・校閲はそれぞれ最大2回、追加検索は最大1回です。再検索後の生成と修復は同じ生成回数の上限を使います。挨拶や、有効な事前校閲済みの経歴概要には、従来の定型・概要の経路を使います。

校閲前の候補は表示・音声化しません。文字・音声画面には、本人の承認済み情報からAIが回答を生成している旨を常に表示します。原文の完全一致だけに回答を制限せず、チームの実績を個人の実績に変えるなどの創作を、引用の検証と意味の校閲で防ぐ設計です。ただし、AIによる校閲も誤りを完全には排除できません。

## 長さと検索対象

文字数はUnicodeコードポイントで数え、文字・音声・経歴概要に共通の方針を適用します。

| 質問 | 上限 |
| --- | --- |
| 名前や一言確認 | 80字 |
| 通常の質問・簡単な自己紹介 | 220字 |
| 詳細の説明 | 400字 |

明示された字数指定も反映します。答えが短くても水増しせず、長すぎる回答は修復の範囲で直します。末尾を切って条件や但し書きを落とす処理は行いません。

Exact Factsは、明示された年・日付・現在の指定を使って選びます。複数年の比較や過去を含む質問にも対応し、期間が重なる矛盾は断定を止めます。モデルに渡す本文から対象外のFactを含む段落を除いても、承認の再確認には加工前の本文を使います。

## 診断と会話記録

根拠不足、モデルの回答断念、引用不成立、校閲拒否、文字数超過、処理失敗を診断コードで区別します。通信失敗や根拠の撤回を、本人についての情報不足として回答しません。文字・音声APIのサーバーログには、固定の理由コードと件数・処理時間・Providerから得られたトークン数だけを記録します。本文・資料・所有者ID・IPなどは含めません。

回答が失敗したときは、時間切れ・中止・想定外の例外を区別したコードと、止まった段階の並びを残します。プレビュー版では、その段階を画面上の失敗表示とローカルの要求記録（固定のコードと数値だけ）で確認できます。詳しくは[JEV版](jev.md#失敗したときの確認)を参照してください。

通常の公開アプリは会話本文・録音・生成音声を永続保存しません。検証者が記録用proxyを起動するローカル検証では、会話・マイク音声・受信した回答音声・進行イベントをPCのGit対象外ディレクトリーへ保存します。これは映像の録画ではありません。保存済み記録は会話終了や再読み込みでも残り、強制終了・通信切断では未送信の末尾が欠けることがあります。公開用資料への自動追加はしません。[記録方法と制約](../voice/README.md#ローカル検証の会話保存)を参照してください。

## 確認した範囲

2026-09-15の引き継ぎ後は、コアテスト268件、型チェック、Workerビルドが通過しました。変更したのは回答生成のプロンプト、候補の機械検証、回答engineの棄権時の扱いで、画面のAPIを差し替える音声ブラウザテストには影響しないため再実行していません。通信を置き換えたテストは、拒否・撤回・中断・長さ・呼び出し上限などの制御を確認するもので、実際のモデルの回答品質を証明しません。

実APIで20問を評価し、見つかった誤断定と誤拒否を修正して対象質問を再確認しました。引き継ぎ後も同じ20問を実行し、質問で尋ねていない事項への「記録がない」の付け足し、面談では硬い言い方、短い回答での担当範囲の抜けを直しました。読み手として意味も照合しています。評価方法と未完了事項は[受け入れ確認](acceptance.md)を参照してください。
