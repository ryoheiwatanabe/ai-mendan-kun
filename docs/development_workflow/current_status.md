## 公開画面が崩れた原因と復旧

公開環境では、静的ファイルの要求をWorkerへ先に渡す設定と、OpenNextビルド時の設定が食い違っていました。さらに独自の静的ファイル配信が認証付きプレビューだけに限定されていたため、公開版のCSS要求がNextの404へ流れていました。

#69で公開版も静的ファイルを返すよう修正しました。認証の確認順序は維持しています。修正前のビルド済みWorkerでCSSの404を再現し、修正後は公開用・認証付き双方で通過しました。続いて公開配信し、実ブラウザでレイアウトと開始ボタンの動作を確認しました。

最初に記録した403（Cloudflare 1010）は、確認用HTTPクライアントでHTML・CSS・JSのいずれにも発生していました。それだけをUI崩れの原因とした説明は不十分でした。実ブラウザのCSS 404と、ローカルWorkerで同じ障害を再現した結果に基づき、上記へ訂正します。

## 統合した機能

- 文字・音声の会話状態、理解した質問の確認、回答停止と復帰。
- JEVによる回答範囲の選別、短い候補の生成、6軸の点検、回数と時間を制限した修復。
- `/admin`での採点・音声設定、設定の版管理、本文を含まない処理計測。
- `/admin/intake`での資料取り込み・確認・承認。重複操作や並行更新の制御。
- 非表示指定、承認・現行版・公開範囲の再確認、管理APIの認証。
- 初期状態ではオフの「開発者モード」。応答速度や回答ごとの処理情報を会話欄の外で確認可能。

JEV版の生成ProviderはOpenCode Go / OpenAIです。共有設定テンプレートは`legacy`のままで、導入環境ごとに回答経路とProviderを選びます。実環境の設定、本人資料、Secret値はGitへ含めません。

## 面接官UXの修正結果

全6件を#70で対応しました。AIによる操作確認であり、参加者を募ったユーザーテストではありません。

| 問題 | 変更と確認結果 |
| --- | --- |
| U1：説明画面との往復で会話・下書きを失う | 説明をダイアログに変更。2往復・下書き・読み位置を保持し、閉じると操作元へフォーカスを戻す |
| U2：回答待ちに書いた次の質問が消える | 送信した質問と下書きを分離。失敗・停止・完了・候補送信・再送を確認。停止時のボタン切替による意図しない次質問送信も修正 |
| U3：狭い画面で候補が会話欄を圧迫する | 会話開始後は候補を開閉式に変更。全18候補の表示を確認。375×667の同じローカル条件で会話欄が約163pxから235pxへ拡大 |
| U4：音声の入力欄が履歴の上にある | スクロールする履歴の直下へ入力欄を配置。320・375・414・768・1366px幅で確認 |
| U5：読み返している途中に末尾へ移動する | 末尾付近だけ新着に追従。読み返し中は位置を維持し、「新しい回答へ」から移動できる |
| U6：手入力でも「マイク使用中」と表示する | 実マイク接続から表示を判定。手入力・準備・聞き取り停止・終了を区別。マイク起動や権限要求の処理は増やしていない |

通常版の会話はタブのメモリ内だけに保持します。終了・再読み込み時には破棄し、永続保存は追加していません。
