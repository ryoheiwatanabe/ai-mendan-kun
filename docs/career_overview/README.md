# 経歴概要の派生文

「自己紹介をお願いします」「経歴を簡単に教えて」など全体の紹介に限り、校閲した完成文を返す任意機能です。会社や時期を指定した質問は通常の検索へ進みます。回答生成・EmbeddingのAPI呼び出しは省略しますが、音声ではTTSを使用します。

管理者が承認済みの現行資料から350文字以内で作成し、主要な経歴の欠落、担当範囲、否定、年代、本人とチームの区別をAIで校閲します。校閲は本人による承認や意味保存の完全保証ではありません。派生文を検索用の資料として登録しないでください。

Git対象外のJSONファイルを用意し、`CAREER_OVERVIEW_JSON`というWorkers Secretに登録します。値はUTF-8で5,120 bytes以内です。Secretをコマンド引数・ログ・環境ファイルに書かず、既存のSecret登録手順でファイルを標準入力へ渡します。本番への登録はデプロイと同様に別途確認します。

| フィールド | 内容 |
| --- | --- |
| `version` | `1` |
| `text` | 校閲した完成文 |
| `reviewedBy` | `"ai"`。本人承認を示す値ではありません |
| `sources` | 根拠1〜10件の`{id, fingerprint}` |
| `sourceSet` | 対象ownerの全現行・承認済み・公開・index済み文書の`{documentId, revisionId, contentHash}` |

根拠はchunkに限ります。`fingerprint`は現行Evidenceの`[id, revisionId, documentId, title, content, contentHash]`をこの順序で`JSON.stringify`し、UTF-8のSHA-256を小文字hexにした値です。`sourceSet`の`contentHash`は文書版のハッシュです。

通常応答では根拠の現在の本文・見出し・ハッシュ・版と、全資料の版集合を照合します。未設定、不正な形式、資料の追加・変更・撤回があれば派生文を使わず通常の検索へ戻ります。音声送信中も、元根拠と全資料の版集合を各送信前に一度のSQLで再確認します。資料の更新後は再作成・校閲・Secretの差し替えが必要です。自動再生成は行いません。
