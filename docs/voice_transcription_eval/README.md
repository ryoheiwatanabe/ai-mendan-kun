# 音声入力の整形比較（2026-09-22）

## 判断

ブラウザー認識を初期選択に残す。Gemini Smart transcriptionへの自動切り替えと、別の整形LLMの追加は保留する。

Smartはフィラーと明確な言い直しを整理できた。ただし、今回の中心となる勤務年数の質問では、過去の勤務歴を現在の勤務へ変える出力が出た。期待する「会社員は何年勤めていましたか？」への整理は未達。JEVの判定精度と、正しい回答を得るまでの時間は未検証である。

変更はこの比較記録のみ。公開アプリ・保護付きプレビューの認識方式と処理は変更していない。

## 方法と範囲

- 対象ソース：`755264ea64f3f953b669e308a6f7d628292a2e63`。
- 事前に8種類の架空質問と保持すべき意味を定義。macOSの`say`（Kyoko、速度165）で合成し、PCM16・mono・16 kHzのWAVに変換。前後に1秒ずつ無音を追加。同じWAVを3方式へ渡した。
- ブラウザー：Chrome 153.0.8010.49、headless。`ja-JP`、`continuous=true`、`interimResults=true`、候補上限3、端末内認識なし。Web Audioの音声トラックを`SpeechRecognition.start(track)`へ渡す。音声ファイルの終端から250 ms後に停止を要求。
- Gemini：`gemini-3.5-transcribe`、`ja-JP`、出力上限512、`store:false`。`verbatim`と`smart`でそれぞれ1回。実行順を質問ごとに交互にした。公開済みコードと同じ基本語彙（AI、生成AI等4件）を使い、固有の人物・会社情報は送っていない。
- Geminiは既存のWorkers Secretを使う一時remote previewで実施。DB・Vectorizeは接続せず、既知の合成音声のSHA-256だけを許可。合計16回を上限とし、12回成功、4回はHTTP 429。上限を超える再試行はしていない。終了後に一時環境を停止し、公開deployment IDが変わっていないことを確認。
- Geminiの成功応答12件は、既存の`GeminiSpeechProvider`へ応答を再生して解析可能なことも確認。再生に追加のAPI呼び出しはない。

これは認識器の比較であり、アプリ全体の操作テストではない。VADによる発話区切り、実マイク、実環境の雑音、公開用語辞書、JEV、回答生成、読み上げは評価に含めていない。ブラウザーへの語彙ヒントはなし。通常の認識器作成経路も現時点では語彙ヒントを渡していない。

最初の仮想マイク経由の試行は全8件で文字が得られなかった。入力経路の問題と認識品質を混同せず、その結果を品質比較から除き、音声トラック経由で全8件を認識した。

中心となる例のSmart出力：

> 組織としての会社員は何年勤められているんでしょうか？

読みやすさは改善しても、過去形の保持は確認できなかった。この変化が音声認識と整形のどちらの段階で起きたかは、今回の出力だけでは特定できない。

現行の機械的な整形も各認識結果へ適用した。ブラウザーが句読点を返さない場合、明確な句読点境界を必要とするフィラー除去はほとんど働かなかった。一方、Gemini通常の「営業ではない仕事」の例は、既存の処理だけでSmartと同じ質問文になった。別LLMによる整形を常に足す根拠にはならない。

## 待ち時間

3方式で結果がそろった最初の6質問を集計。各1回であり、速度の保証や一般的な性能比較には使わない。

| 方式 | 測定区間 | 中央値 | 最短〜最長 |
| --- | --- | ---: | ---: |
| ブラウザー | WAVの再生終端〜確定結果 | 0.316秒 | 0.304〜0.446秒 |
| Gemini通常 | 完成済みWAVのPOST開始〜JSON受信完了 | 2.417秒 | 1.830〜2.931秒 |
| Gemini Smart | 完成済みWAVのPOST開始〜JSON受信完了 | 1.934秒 | 0.941〜2.783秒 |

ブラウザーは発話中から認識している。上記には意図的に設けた250 msの停止待ちを含み、停止要求から確定までは中央値約62 msだった。Geminiは録音終了後に完成したWAVを送るため、認識にかかる待ちを録音後に支払う。Geminiの値には一時previewへの送信とGoogleとの往復も含む。

Smartは通常より4件で短く、2件で長かった。「整形のために必ずもう1回LLMを呼ぶ」構成ではないため、この試行では大きな追加待ちは見られなかった。ただし、単回・合成音声・異なる質問の中央値であり、Smartが恒常的に速いとは判断できない。アプリの無音判定や回答生成を含む総待ち時間、聞き直し回数は未測定。

## 残る確認と次の判断条件

1. 期待する質問へ整形する機能は未完成。整形候補と元の認識文を同じJEV・同じ検索条件に入れ、最終的な判定や回答の改善があるか確認する必要がある。今回、別の整形LLMは評価していない。
2. 数字・否定・条件に加え、時制、対象、質問の数も保持すること。Smartの出力だけでは、元の発話と照合できない。Smartから逐語文と整形文の両方が得られた扱いにしてはいけない。
3. 429で未評価となった専門用語と指示語の2種類、自然な発話、雑音、複数話者、繰り返しでのばらつきは未確認。追加評価は別の上限を決めてから行う。
4. 速度と意味保持の両方を確認できるまでは、ブラウザー優先＋Geminiを選択可能という現在の方針を維持する。期待する質問へ整理する機能は、引き続き未完成として扱う。

独立したAIレビューでも、中心例の時制変化、未評価2種類、少数試行からの一般化を避ける点を確認した。
