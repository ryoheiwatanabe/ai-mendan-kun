## 1. 会話と入力を保持する（U1・U2）

対象見込み：`components/home.tsx`、`components/chat.tsx`、説明表示の部品、関連CSS・ブラウザテスト。5〜7ファイル程度。音声側にも同じ問題があれば共通化する。

- 「このAIについて」を会話の状態を維持して開閉できるようにする。推奨は説明をダイアログで表示する方法。会話中の補助情報を確認するために質問をやり直さずに済む。
- 送信した質問と現在編集中の下書きを分け、過去の要求の失敗処理が新しい下書きを上書きしないようにする。
- 候補送信中も既存の下書きを保持する。再送の操作は失敗した発言の近くに置く方向で検討する。
- 通常版はメモリ内で保持し、明示的な終了・再読み込み時の非保存方針を維持する。

**確認条件：** 2往復と下書きを持って説明を開閉しても、本文・下書き・読み返し位置が残る。質問Aの送信後に書いたBが、Aの失敗・停止・完了で変わらない。下書きがある状態の候補操作で入力を失わない。ダイアログを閉じると操作元へフォーカスが戻る。

## 2. 回答を読みながら次の質問へ進める（U3・U4・U5）

対象見込み：文字・音声のコンポーネント、質問候補、共通CSS・音声CSS、ブラウザテスト。6〜9ファイル程度。

- 会話開始後の質問候補は、必要時に開ける配置へまとめる。候補の見つけやすさと会話の表示面積を同じ画面で確認する。
- 音声画面も、履歴の下から次の質問を入力できる配置へ揃える。履歴が増えても入力まで画面上部へ戻る必要がない構成にする。
- 末尾を見ているときだけ新着に追従する。読み返し中は位置を維持し、新着へ移る操作を置く。
- PCではキーボードだけで入力・送信・停止・候補選択を行えることを確認する。日本語IME変換中に送信しない既存動作を維持する。

**確認条件：** 同じ会話・同じ回答を使って、改善前後の会話表示面積、入力欄へ戻る操作、読み返し位置を比較する。1366×768と320・375・414・768px幅、全18候補、長い履歴で確認。375×667の会話欄163px・候補108pxという現状を改善できたことを記録する。ソフトウェアキーボード表示中の確認は実機確認として別に残す。

## 3. 音声状態を操作と一致させる（U6）

対象見込み：`components/voice-chat.tsx`、`lib/voice/browser.ts`、型定義と関連テスト。3〜5ファイル程度。

- 「会話が始まっている」と「実際にマイクを収音している」を別の状態として扱う。
- 手入力・収音中・一時停止・回答中・終了の表示と操作可能なボタンを照合する。
- マイクの許可拒否、認識失敗、回答停止後も、再開や手入力へ進めることを確認する。

**確認条件：** マイクを開いていない手入力では使用中と表示しない。開始・停止・終了で表示が実際の収音に一致する。表示変更のために新たなマイク起動や権限要求を増やさない。

## 4. 面接官の作業を通して再検証する

Computer Useで次の課題を通し、操作の消失・入力への戻り・読み返しを確認する。

1. 経験について質問し、回答中に次の質問を書く。
2. 過去の回答を読み返し、その内容を踏まえた質問をする。
3. 説明を開閉し、同じ会話を続ける。
4. 待機・失敗・停止を経験した後で、下書きから質問を続ける。
5. 音声画面で手入力し、長い履歴から次の質問へ進む。
6. 会話を終了し、保持していた内容が消えることを確認する。

コード変更に合う回帰テスト・型チェック・ビルド、独立した差分レビュー、最新commitの確認を経てPRをマージする。公開デプロイは別工程で扱う。自動テスト・AIの画面操作・本人の受け入れ結果を混同しない。

## 今回の必須改善に含めない案

回答からの深掘り候補、面接メモ／持ち帰り用コピー、文字と音声の切替時の会話共有は、実際の面接官の作業を確認してから採否を決める。6件の修正と同時に追加すると、既存操作を直した効果を判別しにくくなる。
